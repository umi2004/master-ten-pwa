# Master Ten ゲーム仕様

## 1. 文書の位置づけ

本書は Master Ten ルール版 `2.0.0` の規範仕様である。主要資料は `master-ten-research-and-spec.md` だが、参考製品で未確認の挙動は再現せず、本書で Master Ten 独自仕様として固定する。

## 2. 盤面表現

- 列数は常に `9`。
- セル値 `Cell` は整数 `0..9`。`0` は空所、`1..9` は生存数字である。
- `Board` は `cells: Cell[]`、`width: 9`、`logicalLength: number` を持つ。
- `cells.length === logicalLength` を正規形とする。末尾の未使用セルを配列へ持たない。
- 行 `r`、列 `c` の一次元インデックスは `r * 9 + c`。位置はインデックスではなく `{ row, column }` として公開する。
- 最終行は 1～9 セルの部分行を許す。空盤面だけは `logicalLength = 0`、`cells = []`。
- 部分消去では、生存数字を左右へ詰め直さない。消去位置を `0` にする。
- 初期問題は9列へ空所なく密に置き、Master帯に応じて6～10行を目標とする。公開問題ごとに `initialRows` を記録する。
- プレイ中の最大論理行数は 48。検証解がこれを超える候補は公開しない。

## 3. 数値条件

2セルの値を `a`、`b` とすると、どちらも生存数字で、次のいずれかを満たすときだけ数値条件を満たす。

1. `a === b`
2. `a + b === 10`

`5` と `5` は両方を満たすが、1つのペア手として1回だけ列挙する。ペアは小さいインデックスを先にした正規順で表す。

## 4. 接続条件

### 4.1 直線接続

水平、垂直、45度の斜めを含む8方向を使用する。各生存セルから各方向へ進み、盤面の論理範囲内で最初に遭遇した生存セルだけをその方向の候補とする。

- 途中の `0` は何セルでも越えられる。
- 途中に生存数字があれば遮断され、その先の数字は候補にならない。
- 最初の生存セルと数値条件が不一致でも、その先を探索しない。
- 逆方向から得た同じ2セルは重複させない。

### 4.2 行またぎの読み順接続

インデックス `i < j` の2つの生存セルについて、次をすべて満たす場合に読み順接続候補とする。

- `i + 1 .. j - 1` の全セルが `0`。
- `floor(i / 9) !== floor(j / 9)`、すなわち少なくとも1つの行境界をまたぐ。
- 両端が数値条件を満たす。

これは厳格な右端・左端だけでなく、行末側と次の行頭側にある空所を越える Master Ten 独自の一次元接続である。直線接続と同じペアになる場合は1回だけ列挙する。

## 5. ペア消去と正規化

合法な `PairMove` を適用すると、対象2セルを `0` にする。その直後、同じ原子的操作内で次の順に正規化する。

1. 現在の論理行を9セル単位（末尾は部分行）で分割する。
2. 含まれるセルがすべて `0` の行を削除する。部分最終行も全セルが `0` なら削除する。
3. 残る行を順序を変えず上へ連結する。
4. `cells.length` と `logicalLength` を連結後の長さに更新する。

正規化はペア消去直後に必ず1回実行する。選択中、描画中、保存時だけ遅延実行してはならない。

## 6. 数字追加

`AddNumbersMove` は、勝利前で、追加残数が1以上、生存数字が1つ以上のとき合法である。合法ペアの有無は問わない。

1. 現盤面の生存数字を上から下、左から右の読み順で抽出する。
2. 抽出列を現在の `logicalLength` から連続して末尾へ追加する。
3. 最終行が部分行なら、その続きから追加する。
4. 過去の `0` は埋めない。削除済みセルも複製しない。
5. `additionsRemaining` を1減らし、`additionsUsed` を1増やす。
6. 追加後も9列幅で解釈し、論理長を新しい配列長へ更新する。

Master問題の初期追加残数は全問5。追加後に48行を超える状態は生成品質ゲートで除外し、実プレイで到達した場合は追加を拒否して理由を表示する。

数字追加は常時選択肢としてソルバーへ含める。UIは追加の早すぎ・遅すぎが盤面を悪化させ得ることを説明する。

## 7. 勝敗

- 生存数字が0になった直後に `WON`。
- 生存数字があり、合法ペアが0、追加残数も0なら `LOST`。
- それ以外は `PLAYING`。
- 探索の `UNKNOWN` はゲームの敗北状態ではない。

## 8. 操作仕様

### Undo

- 成功したペア消去または数字追加の直前状態を履歴へ保存する。
- 1手戻すたび直前の完全な状態へ戻す。選択だけの変更や無効操作は履歴へ入れない。
- Undo回数を増やし、ノーアシスト条件を失う。戻した手を再実行しても使用記録は消さない。

### ヒント

- 現状態から `SOLVED` と検証された完走経路の先頭手だけを返す。
- キャッシュは状態キーが完全一致する場合だけ使う。
- 解経路外の操作後は再探索する。
- 次手が数字追加の場合も提示できる。
- `UNKNOWN` または安全性を確認できない場合は手を返さず、「現在この局面の安全なヒントを確認できません」と表示する。
- ヒント要求回数を記録し、ノーアシスト条件を失う。

### リスタート

- 確認後、同じ問題ID、seed、初期盤面、初期追加残数へ戻す。
- リスタート回数は保持し、手数、履歴、経過盤面を初期化する。
- リスタート使用はノーアシスト判定には含めないが、結果へ表示する。

## 9. 自動保存

成功した各操作、Undo、ヒント使用、リスタート、設定変更、画面離脱時にローカル保存する。保存内容と検証規則は `architecture.md` に定義する。読込不能データは現行セーブから隔離し、初期画面は必ず起動可能にする。

## 10. 識別子と版

- ルール版: `1.0.0`
- 生成器版: `1.0.0`
- 難易度版: `1.0.0`
- 保存スキーマ版: `1`
- 問題ID: `master-r1-g1-d1-<seed>`。`seed` は英小文字・数字・ハイフンの安全な識別子。
- 問題IDはモード、ルール版、生成器版、難易度版、seedを一意に特定する。
- `PuzzleDefinition` は初期盤面、論理長、初期行数、追加上限、全版、seed、検証メタデータを持つ。

版不一致の保存データを暗黙変換しない。明示的なマイグレーションがない場合は隔離して日本語で説明する。

## 11. V4 Master問題の追加証明

Master候補の追加可能回数は5である。採用には追加上限0～4を各`UNSOLVABLE`、上限5を`SOLVED`と証明し、`minimumAdditions = 5`かつ`minimumAdditionsProven = true`とする。探索打切りは`UNKNOWN`であり、不能証明へ読み替えない。

数字追加の合法条件は、`PLAYING`、追加残数が正、生存数字が正、追加後48行以下、だけである。合法ペアが残っていても追加できる。生存数字を読み順で現在の論理末尾へ複製し、削除穴は埋めず、部分最終行の続きから配置する。UI、ヒント、AI、生成器、完全ソルバーは`core/addNumbers.ts`と`core/gameState.ts`の同じ遷移を利用する。

## 12. V4解経路の役割

問題メタデータは`minimumAdditionSolution`、`minimumMoveSolutionAtMinimumAdditions`、`lowHeightSolution`、`recommendedHumanSolution`を別々に持つ。最適性が未証明なら証明フラグを偽とし、最初にDFSが見つけた経路を最短と表示しない。ヒントは検証済み`recommendedHumanSolution`を優先する。
