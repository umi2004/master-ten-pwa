# Master Ten 難易度モデル

## 1. 版と目的

難易度版は `1.0.0`。計算量だけを「難しさ」とみなさず、プレイヤーが目で候補を探し、順序を判断し、数字追加後の盤面を追跡する負荷を複数特徴量から評価する。65～94点だけを公開Master候補とする。

## 2. 計測範囲

- 分岐、強制手、最大高さ、フェーズ難度は、検証済み完走経路上の各局面で測る。
- 初期誘惑手は、初期合法手を全て1手適用し、その後を三状態ソルバーで再探索する。
- 初期誘惑手監査が1件でも `UNKNOWN` なら候補を採用しない。
- `estimatedSolutionCount` は版1では「初期合法手のうち、明確な悪化なしに完走可能な手の数」の保守的代理値であり、完全な全解数ではない。
- `provenOptimal` と `minimumAdditionsProven` は別。任意解が見つかっても最適手数証明とはしない。

## 3. 特徴量

| 特徴量 | 定義 |
|---|---|
| `initialMoveCount` | 初期合法ペア数 |
| `nodesExpanded` | 保存解を得た実用DFSの展開数 |
| `bestKnownSolutionLength` | 数字追加も1手と数えた保存解長 |
| `minimumAdditions` | 追加上限を0から増やして初めて `SOLVED` になった解の追加数 |
| `minimumAdditionsProven` | それより少ない各上限が全て `UNSOLVABLE` と証明済み |
| `averageBranching` | 保存解経路上の合法遷移数平均。追加だけの局面は1 |
| `maximumBranching` | 保存解経路上の最大合法遷移数 |
| `forcedMoveRatio` | 保存解経路上で合法遷移が1つだけの局面割合 |
| `trapMoveCount` | 初期手のうち、解なし、最小追加増加、または残り手数50%以上悪化となる手数 |
| `estimatedSolutionCount` | 初期手のうち上記の明確な悪化がない完走可能手数（最低1） |
| `maximumRowsDuringSolution` | 保存解再生中の最大論理行数 |
| `phaseDifficulty` | 解経路を3等分し、各区間の平均分岐を0～100へ写像 |

誘惑手を「最短解にない」という理由だけで数えない。少し長い正常解を誤手扱いせず、解不能、追加増、50%以上の手数悪化という明確な害を条件にする。

## 4. 版1スコア

版1は次の生スコアを整数丸めし、上限94とする。

```text
48
+ min(18, bestKnownSolutionLength × 0.45)
+ minimumAdditions × 5
+ min(12, trapMoveCount × 3)
+ min(8, maximumBranching × 0.6)
+ min(6, (1 - forcedMoveRatio) × 6)
+ min(5, max(0, maximumRowsDuringSolution - 8))
```

探索ノード数は記録するが、版1の点数へ直接加えない。ソルバー実装や手順序変更だけで難易度が大きく変動するのを避けるためである。将来、実プレイデータを個人情報を収集せず端末内だけで確認できる場合も、係数変更時は難易度版を上げる。

## 5. 品質上の補正

点数が65以上でも、次の候補は不採用とする。

- `UNKNOWN`、解再生失敗、初期合法手0
- 8～12初期行の目標外（調整理由がない場合）
- 最大48行超過、追加3回超過
- 構造署名重複、単純な数字クラス置換だけの重複
- 全局面の安全ヒントを検証できない
- 長いだけの一本道、視認不能、極端なスクロール

版1は人間の実測クリア率を持たないため「Master候補」という設計評価であり、母による実プレイ後に理不尽さと楽しさを別途レビューする。
